# ADR-0024: The 360 family: one shared layout lib, sections as configuration, capabilities embedded by account id

- **Status:** Accepted (names and URLs amended by [ADR-0026](0026-full-profile-naming.md): Customer full profile / Agent full profile)
- **Date:** 2026-10-02
- **Source:** Plan Phase 4 (gate: case `BIL-2026-003318` → subscriber 360 → back without a full reload)

## Decision
1. **`libs/layout-360`** (tags `type:layout family:360`, build-time, not shared, not a remote): `Layout360Component` renders profile banner → KPI strip → section grid (span 1–3). `PanelHostComponent` loads a capability into a section, and a failure stays in that panel with Retry. `L360SectionDirective` marks sections the app renders itself. `CaseListComponent` is presentational. The layout makes no HTTP calls.
2. **Sections are configuration** (`Section360[]` in each app's `*.sections.ts`): `{ id, title, span, remote?, exposedModule?, inputs?, entitlement? }`. A capability gets only the `panelInputs` its section lists.
3. **Apps:**
   - `mfe-subscriber-view` at `/subscribers/:id`: Account & lines (`mfe-cap-account-view`), Usage & billing (`mfe-cap-usage-billing`), Open cases, Linked dealers
   - `mfe-partner-view` at `/partner-360/:id`: Findings, Open cases, Linked subscribers, plus activation, quality and chargeback KPIs
4. **Capabilities used on both case and 360 screens accept either input contract** (contracts v1.3, additive `SubscriberCapabilityInputs { accountId }`): `mfe-cap-account-view` and `mfe-cap-usage-billing` call `/api/accounts/:id[/usage]` when given `accountId`, else the case endpoints.
5. **Navigation stays with the shell:** `OPEN_SUBSCRIBER_360` (existing) and `OPEN_PARTNER_360` (v1.3, additive). Registry entries carry `opensProfile: 'SUBSCRIBER' | 'PARTNER'`. Emitters:
   - the Case management overview ("Subscriber 360" / "Partner 360" buttons)
   - the 360 cross-links
   - the global header search, `mfe-cap-subscriber-search`, which replaces the placeholder search box and is embedded through the shell's capability slot in compact mode
6. **No audit log on 360 screens** (resolved decision in the plan), enforced by `npm run check:layouts` together with: Layout360Component required, no tab bar, no own capability loading.
7. Generator: `--kind=domain --family=360` scaffolds routes (`:profileId`), a sections file and a profile component on the shared layout. Set `opensProfile` in the shell registry by hand (the generator cannot know the profile kind).

## Consequences
- The Phase 4 gate is `apps/shell-e2e/src/phase-4-360.spec.ts` (6 tests). A `window` marker proves there is no full reload across case → 360 → back → another case.
